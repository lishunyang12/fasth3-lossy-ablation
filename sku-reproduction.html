在 5000 和目标 SKU 上运行

先按照完整说明准备固定依赖、模型权重与 AdaLN 缓存，编辑机器路径。两台机器使用同一源码版本，保持相同 GPU 数、输入和缓存文件。

git clone https://github.com/lishunyang12/h3-optimizations.git
cd h3-optimizations
git checkout 428123a8ca3d334b6a0339f6ead834f8c1093a5d
python3 scripts/sku_benchmark.py prepare --variant avatar5 --output /opt/h3-runtime-avatar5
python3 scripts/sku_benchmark.py prepare --variant reference --output /opt/h3-runtime-15s
python3 scripts/sku_benchmark.py prepare --variant output-fusion --output /opt/h3-runtime-15s-output-fusion
cp configs/sku-assets.example.json /tmp/h3-assets.json
# 编辑路径、下载固定权重、构建缓存后：
python3 scripts/sku_benchmark.py suite --cases main   --assets /tmp/h3-assets.json --gpus 0,1,2,3,4,5,6,7   --output /results/pro5000
# 目标机器使用同一命令，将输出目录改为 /results/pro5500。
python3 scripts/sku_benchmark.py compare   /results/pro5000/5s-avatar-ref2va-4step/result.json   /results/pro5500/5s-avatar-ref2va-4step/result.json   --output /results/avatar-comparison.json

两个 15 秒 case 同样使用 compare。4-GPU 的八步 Omni 配置须单独运行。GPU 架构、数量、显存或空闲条件不符合时，程序退出并给出原因。

如何保证比较口径一致

固定并记录

  • 原始提示词、参考图、种子、帧数、步数及精度配置。
  • 模型与缓存字节哈希、实际源码与二进制指纹、依赖版本。
  • GPU 型号、显存峰值、驱动、频率、功耗、CPU 与 PCIe / RDMA 拓扑。
  • 预热单独保存；计时覆盖本地请求至完整 MP4 落盘。

检查与解释

  • 四步运行检查真实 DiT 次数、量化 fallback、VAE 和 RDMA 证据。
  • 正式计时外检查视频帧数与完整音视频解码；保留 MP4 和日志。
  • 不同配置、权重、源码、依赖或受外部 GPU 作业干扰的结果拒绝配对。
  • CPU、互连、功耗和频率仍影响端到端时间；这是同工作负载的系统比较。

复现数字人推理序列不包含聊天、RTMP 或直播播放延迟。量化配置属于有损路线；不同 GPU 的输出字节差异单独报告，不自动等价于画质优劣。
